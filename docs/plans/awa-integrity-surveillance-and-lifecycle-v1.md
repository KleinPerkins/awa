**Goal:** give AWA an honest, runnerless self-surveillance layer — one engine-side evaluator, one
status-last atomic `status.json` of record, fail-open Cursor-hook fast checks + a `local-jobs`
launchd deep sweep, loud native (opt-in Slack) alerts that are always *attempted* with honest
delivery accounting, and a thin private static HTML console — and close the entry/lifecycle root
causes that let the 2026-08-24 DEGRADED state accumulate silently, **without changing the guard's
safety contract**.

**Architecture:** `engine/integrity.py` (one evaluator + one registry/reducer) is driven by one CLI
interface `awa-engine integrity verify --profile fast|deep --trigger cli|beforeShell|stop|launchd`;
one evaluation writes one status-last, generation-validated commit to
`~/.local/state/awa/integrity/status.json` under a dedicated integrity lock held **only** by
`_commit()`. Every consumer — CLI verbs, fail-open hooks (fast), the `com.kleinperkins.awa-integrity`
launchd deep sweep, the alert dispatcher, and a deterministic self-staling static HTML console —
derives from that one evaluator and that one file. Kernel-first is preserved. **AWA owns the product;
`~/dev`'s `local-jobs` owns the live launchd job and external hook wiring** (ADR 0020 §8).

**Tech stack:** Python 3.9 stdlib (`json`, `os`, `sqlite3` live `mode=ro`+`query_only`, `fcntl`,
`hashlib`, `html`, `socket`, `subprocess`), Bash 3.2 hooks, macOS `osascript`/`launchd`/`security`
(Keychain), Slack Web API (`conversations.open`/`chat.postMessage`), `unittest`, the AWA
contract-freeze UAT, and the runnerless `KleinPerkins/*` PR-automation Apps.

## Global constraints

- **No guard relaxation, ever.** `engine/guard.py::decide_shell` and
  `kernel/hooks/worktree-guard.sh::check_probe` keep exact behavior. The composite
  `beforeShellExecution` entry returns the guard's stdout/stderr **and exit code byte-for-byte**.
  Guarded by `test_guard.py`, `test_guard_hook_wrappers.py`, and a new byte-for-byte parity test.
- **Kernel-first.** New code is engine-side; the kernel guard/cleanup work with the engine
  uninstalled (`test_kernel_off_matrix.py` stays green).
- **One evaluator, one trigger interface, one commit.** Every surface runs
  `integrity verify --profile … --trigger …`; one evaluation → one `_commit`. Only `_commit()`
  acquires the dedicated integrity lock; sweep/hook wrappers never acquire it.
- **Honest non-green.** Stale/malformed/missing status is non-green; while non-green, failure of ALL
  configured alert paths is RED. Alerts are always *attempted*, never assumed delivered/seen.
- **Reconciliation, not GC.** Leases/worktrees/sessions are classified read-only via
  `awa_roots.disposition`; PID/boot are diagnostic only. No autonomous deletion; every removal routes
  through existing kernel gates. `chaos-scheduler` is no-touch via a **generic predicate** (host config
  supplies the path).
- **Runnerless.** Local `local-jobs` launchd + fail-open hooks only. No GitHub Actions runner, no paid
  infra.
- **No Cursor Canvas; never touch chaos-scheduler.** The console is static HTML, not `*.canvas.tsx`.
- **Secrets stay out of git/logs/exports/console.** Slack bot token in Keychain; operator Slack user id
  in a `0600` config; no secret/raw-evidence/path ever logged, rendered, or exported.
- **Python 3.9 / Bash 3.2** on any kernel/hook path.
- **Version discipline:** new behavior is a MINOR bump from live latest (expected `1.6.0`; recompute at
  release). Accepted ADR 0020 and this plan stay byte-identical after approval. The frozen
  `contracts/awa-contract.v1.json` bytes are **not** touched (the hook successor is a new file, §4.8).

## 1. Purpose

The 2026-08-24 incident refuted the guard-bug hypothesis but exposed that AWA has **no
self-surveillance**: 64 orphaned worktrees, 2 unreconciled leases (roots absent, but *not*
removal-authorized), 12 dangling in-namespace sessions, and a latent recovery-scan error accumulated
with nothing watching. This plan builds the minimum honest surveillance + alerting + interface and
fixes the entry/lifecycle root causes so a DEGRADED state is **visible and loud** and the lifecycle
stays **bounded and safe**.

## 2. Scope and non-goals

**In scope:** one evaluator + registry/reducer driven by one `verify --profile --trigger` interface;
a status-last atomic `status.json` + generation-tagged derived artifacts + bounded history; a live
`mode=ro`+`query_only` SQLite read path; CLI `view`/`verify`/`console`(+`sweep`); fail-open debounced
`beforeShellExecution`/`stop` fast checks via a concrete `awa-hook-owner.v2.json` successor + composite
guard entry + detacher; a `com.kleinperkins.awa-integrity` deep sweep (AWA ships the executable + label/
schedule contract; `~/dev` `local-jobs` schedules/activates it); an alert dispatcher (native always
*attempted*; opt-in Keychain Slack DM with bounded timeout/retry/429; all-configured-fail-while-nongreen
⇒ RED); a deterministic redacted private static HTML console with a `fresh_until` clock-only script; an
installer/uninstaller/config that never activates the host job and never touches external hook rows; M2
read-only lifecycle reconciliation (`lifecycle_reconcile.py`), a digest-bound recovery **quarantine**
verb + the `.trash` migration, and a Safe-Workspace **session-handoff** role; biting hermetic tests +
fault injection; the exact **two** `~/dev` PRs.

**Non-goals:** any guard change; auto-deletion on pid/boot; a persistent server or menu-bar/Tauri app
for M1; any `chaos-scheduler` reuse; any Cursor Canvas; any GitHub runner/paid infra; multi-machine
fan-out; a plugin framework; any arbitrary export in M1 (M4 owns it); `immutable=1` reads; an AWA plist
template; AWA writing external hook rows.

**4.2 Severity reduction (deterministic).** Per invariant `green|degraded|red|unknown`. Overall:
**green** ⟺ every required invariant green **and** every required trigger fresh (4.4). **degraded** =
safety intact but action required; a non-safety-critical `unknown` ⇒ ≥ degraded. **red** = a
safety-critical invariant (`guard_safety`,`parity`) red/unknown; or status malformed/missing/stale;
or evaluator crash; or (non-green) all configured alert paths failed. Lifecycle classification uses
root existence, Git registration, `awa_roots.disposition`, lease file, and pending journal/recovery
ambiguity — **PID/boot diagnostic only**. `entry_handshake` derives only from explicit handoff
metadata: until M2 receipts exist it is `absent|pending|unknown` — never invented retry history.

**4.3 Public projection `awa-integrity-public/v1`** (console/export input): a CLOSED subset — no
absolute paths, no secrets, no raw evidence — `overall`, per-invariant `{id, severity,
redacted_reason}`, `orphans`/`recovery` counts, bounded recent history `{generation, overall,
generated_at}`, `last_checked_age_s`, and `fresh_until`.

**4.4 Freshness (read time).** `launchd` (deep) is required: fresh ⟺ `now - triggers.launchd.
last_success ≤ DEEP_BOUND` (default 24h). Fast triggers advisory. Missing/old required trigger ⇒
`surveillance_freshness` non-green ⇒ overall non-green.

**4.5 Status-last, generation-validated commit** `integrity._commit(status, *, profile, trigger)`:
acquire the **dedicated integrity lock** (`fcntl.flock` on `~/.local/state/awa/integrity/.lock`,
`0600`; **never** `state_root_lock`; **only** `_commit()` acquires it). Then: (1) `N = prev_gen+1`,
`transition_id` iff overall severity changed; (2) write each **generation-tagged derived artifact
first** into its own child dir (`history/<N>.json`, `public/<N>.json`, `console/<N>.html`,
`outbox/<N>.json`): `O_EXCL` temp in that child dir → full write → **`fchmod 0600` (before the file
fsync)** → `fsync(fd)` → `os.replace` to `<N>` → **`fsync` that artifact's immediate parent child dir**
(`history/`/`public/`/`console/`/`outbox/`); if a child dir was created this pass, also `fsync` the
**integrity root**; a prune/unlink of a superseded gen file `fsync`s that child dir after the unlink;
(3) build `status.json` bytes = full status + `generation` + `transition_id` + each artifact's
`{gen, path, sha256}`; (4) **replace `status.json` LAST**: `O_EXCL` temp in-dir → full write →
**`fchmod 0600` BEFORE `fsync`** → `fsync(fd)` → `os.replace` → **`fsync` the integrity root dir**;
(5) release lock; dispatch alerts (4.6) **outside** the lock, then persist delivery via the CAS
receipt commit (4.7a). Readers trust a derived artifact **only** if
`status.json` references its gen+sha256; pre-commit orphan gen files are harmless/GC-able. A
non-increasing generation is refused (`StaleGenerationError`).

**4.6 Live SQLite read** `integrity._ro_conn()`: `sqlite3.connect("file:{db}?mode=ro", uri=True)`,
then `PRAGMA query_only=ON`, then an explicit read transaction. Rows in the live WAL are visible;
writes are refused. **Never** `immutable=1`; **never** `engine.state.State()`. A frozen snapshot, if
ever needed, uses the SQLite **online backup API**.

**4.7 Alerts.** Always *attempted* on a worsening flip; per-channel `accepted|failed`; dedupe by
`transition_id`; bounded reminders; no alert-about-alert. `osascript`/Slack ok = **accepted**, never
seen. **While non-green, failure of ALL configured paths ⇒ RED**; Slack opt-out makes native the sole
configured path (native failure ⇒ RED). Fallback by trigger: sync CLI writes stderr; local-jobs
persists durable job logs/status; detached hooks **cannot** promise visible stderr (they still record
RED in status). Slack: Keychain bot token + `0600`-config user id → `conversations.open` →
`chat.postMessage` closed redacted payload; **bounded total connect+read timeout, bounded retry count
+ backoff, capped `429 Retry-After`, no unbounded waits**.

**4.7a Alert-receipt CAS bookkeeping commit** `integrity.commit_alert_receipt(expected_generation,
transition_id, outcomes)`: the evaluation commit (4.5) publishes the authoritative transition + an
**immutable pending `outbox`** entry; the dispatcher (4.7) runs **outside the lock**; then this typed
follow-up **reacquires the integrity lock**, **CAS-verifies** the current status `generation` +
`transition_id` still match, writes a **NEW immutable delivery-receipt artifact** (`receipt/<M>.json`)
+ regenerated `public/<M>.json`/`console/<M>.html`, and advances `status.json` **status-last** to a
**bookkeeping generation `M` under the SAME `transition_id`** with `alert.delivered = {native, slack}`
∈ `accepted|failed|opted_out`. It performs **NO re-evaluation, emits NO new alert/outbox, and cannot
recurse**. On CAS mismatch (a newer evaluation superseded it) the receipt is **recorded stale/audited
and never overwrites the newer status**. `receipt/` is a derived child dir under the same durability
rules (4.5).

**4.8 Hook-owner successor.** A **new file** `contracts/awa-hook-owner.v2.json` (schema
`awa-hook-owner/v2`) adds three roles — `worktree.shell-guard-composite` (beforeShellExecution),
`worktree.stop-observer` (stop), `worktree.session-handoff` (sessionStart) — successor to the v1

## 7. Rollback

- **Before merge:** correct with a new commit; never amend a pushed commit.
- **After merge, before release:** revert via a normal PR. **Rollback order (host triggers OFF first):**
  `~/dev` `local-jobs` deactivate + remove external hook rows → wait for / bounded-kill any in-flight
  observer/sweep workers → revert the `~/dev` Host-Wiring PR → revert the AWA release/pin/runtime →
  optionally remove the derived `~/.local/state/awa/integrity/` state (pure derived; the next
  verify/sweep regenerates it).
- **After release:** never move/delete a tag; publish a corrective patch and revert the Skills pointer +
  `~/dev` wiring through their governed PRs.
- **State safety:** deleting `~/.local/state/awa/integrity/` is non-destructive. Lifecycle actions are
  reversible only through the recovery/quarantine artifacts they must capture first.
