## 1. Purpose, requirements and scope

Implement one factual bookkeeping path after concrete semantic acceptance:
trusted agent-mediated native chat/worktree observations, independent physical
Git validation, and a private association record. Report provenance and age;
grant no writer ownership, lease, admission, protection or cleanup authority.

The approved Dev integration PRD
`PRD-54aec621-9236-53d2-87b7-9a60ef4ec92e-47748eb9-9653-5148-96b2-80bf7b94ca63`
provides REQ-INT-009 (workspace/isolation), REQ-INT-010 (lifecycle separation),
REQ-INT-015 (governed authoring), REQ-INT-019 (owner delivery) and REQ-INT-020
(honest status). This plan does not claim association records satisfy the PRD's
separate writer-exclusion or destructive-action requirements. The operator's
2026-11-01 direction adds the proposed association definition. The AWA owner must
bind that interpretation through concrete acceptance; do not invent an approved
AWA PRD or describe the private coordination amendment as frozen authority.

Initial scope is local macOS Codex desktop, a machine-local AWA store, one current
physical non-primary linked worktree per chat, many chats per worktree, and
multiple attachments per chat. CLI/cloud/remote/other-OS host associations and
multiple simultaneous current roots are unsupported in v1. Dirty content,
detached HEAD, and an in-progress Git operation do not by themselves invalidate
an association; no repository content/status scan is required for bookkeeping.

Preserve all accepted Cursor, kernel, lease, finish, cleanup, hard-no-touch and
ADR 0026 boundaries. No A02, hook installation, app-server launch, MCP migration,
server-guard change, new service/auth connection, daemon or automatic activation.

## 2. Concrete interfaces and trust

Proposed interface under the existing engine CLI:

```text
awa-engine codex-association record   < request.json
awa-engine codex-association refresh  < request.json
awa-engine codex-association inspect --chat-id CHAT
awa-engine codex-association inspect --worktree ABSOLUTE_ROOT
```

`record` creates a chat snapshot only with `expected_revision=0` and no existing
record. `refresh` requires the exact positive existing revision. Both accept only
stdin, never a source file path, arbitrary command, raw native response, or
caller-selected state directory. `inspect` is read-only and never refreshes,
probes native tools, repairs state or changes the target worktree. All responses
are strict JSON and use closed reason codes. Invalid input exits 2; a valid
request that cannot establish/publish its observation exits 1; completed
recording/inspection exits 0. Exit 0 for inspection can still mean unknown/stale.

There is no new MCP registration tool in the initial body. A later thin MCP
exposure must reuse this exact receiver contract, with explicit mutation scope.
Native tools are called by the reporting agent, not by AWA's existing MCP server.
The initial source adapter expects `mcp__codex_app__list_artifacts` in that chat
context and `mcp__codex_app__read_thread` for the claimed chat, projecting only
worktree attachment identifiers/root/workspace-root and thread ID/current cwd.
Missing source fields are unknown, not synthesized. Native turn status is not
archive status. No source title, summary or message content is needed.

Trust the reporter to use the correct invoking chat and faithfully convey those
observations. Validation, timestamp checks and hashes cannot detect a dishonest
reporter. The receiver must reject `host-authenticated` or any unsupported trust
label. An authenticated host bridge is not an implementation dependency of this
accepted-as-proposed agent-mediated profile; it would be a different profile.

## 3. Closed request ABI

Schema literal: `awa-codex-association-request/v1`. Every request has exactly:

| Key | Type and meaning |
|---|---|
| `schema` | Literal schema above |
| `action` | `record` or `refresh`, equal to CLI verb |
| `expected_revision` | Integer 0 for create, positive for refresh; booleans refused |
| `host_scope` | Literal `codex-desktop-local`; namespace within this machine-local store, not a global machine identifier |
| `chat_id` | Exact opaque native chat ID |
| `trust` | Literal `trusted-agent-mediated` |
| `adapter_revision` | Literal AWA-owned `codex-association-agent/v1`, not a claimed host API revision |
| `outcome` | `current` or `unknown` |
| `reason` | `none` for current; otherwise one of the uncertainty reasons below |
| `reported_started_ms`, `reported_completed_ms` | Integer UTC Unix milliseconds, reporter-supplied |
| `before`, `after` | Native snapshot objects for current; null for unknown |

A native snapshot has exactly `chat_id`, `current_workspace`, `attachments`.
`attachments` is the complete projected worktree-attachment set returned in that
native query, not the PR/document attachment set. Each entry has exactly
`attachment_id`, `root`, `workspace_root`; all are source-provided strings.
Optional source fields that are absent cannot be invented to make this packet.
Normalize order by attachment ID only, never normalize opaque ID bytes. Repeated
identical IDs are rejected rather than counted twice; conflicting IDs refuse.

For current, both snapshots must have the top-level chat ID, identical current
workspace strings and identical normalized attachment arrays. Select the root
deterministically before target access:

1. Retain entries for which `root` is an ancestor/equal of `workspace_root`, and
   `workspace_root` is an ancestor/equal of `current_workspace`, using lexical
   path-component boundaries. Group retained entries by exact `root` string.
2. Require exactly one root group. Zero groups is unavailable; several distinct
   groups, including nested candidate roots, are ambiguous. Do not pick first,
   newest, longest prefix or most accessible. Several IDs in one root group are
   allowed and form the selected-attachment set.
3. After policy checks, verify that the physical Git top-level for that root and
   the reported current workspace are both exactly the selected canonical root,
   with the same per-worktree and common Git directories. Every selected
   `workspace_root` must physically remain inside that root. Reject symlinked or
   changed components. A subdirectory workspace is valid only by this agreement.

All other attachment IDs are non-currently-validated observations. Their roots
are never probed or used to repair a failed selection. A valid existing-chat
refresh with a source-selection conflict follows the conservative unknown
transition below; it cannot promote an alternative root by guessing.

`unknown` reasons are `native_unavailable`, `association_conflict`,
`archive_observed`, `worktree_missing`, `identity_changed`, `source_unsupported`,
`physical_identity_unavailable`, `policy_refused`, `clock_unavailable`.
This is a trusted reporter's conservative loss-of-current observation, not an
authenticated archive/deletion event. Null snapshots cannot create a positive
association. Unknown on create returns unknown without creating a record; unknown
on refresh can clear only that chat's bookkeeping current pointer, preserving
its previous verified edges as historical. It never deletes a file/worktree,
releases a lease, clears a cleanup blocker or registers a new edge.

Shared limits: request <=131072 bytes, UTF-8 strict JSON, depth <=8, <=64
attachments/snapshot, <=256 UTF-8 bytes/ID, <=4096 bytes/path, integer range
0..2^63-1 with no bool/float/non-finite substitutions, duplicate and unknown keys
refused at every object level. IDs are nonempty, trim-stable and contain no
control characters; preserve their bytes without Unicode normalization. Paths
must be absolute, trim-stable, NUL/control-free and lexically normalized, without
`~`, `.` or `..` components. Request timestamps must be ordered, span <=30000 ms,
and complete within 60000 ms before the receiver's current UTC sample with no
more than 5000 ms future tolerance. These are checks on trusted claims, not proof
of source authenticity. Invalid/over-limit packets produce zero state writes.
Reject lone Unicode surrogates even when introduced by JSON escapes.

Canonical function C(x) is exactly UTF-8 encoding of Python
`json.dumps(x,ensure_ascii=False,allow_nan=False,sort_keys=True,separators=(",",":"))`,
with no LF. All object keys in these closed ABIs are ASCII. Canonical storage is
C(record)+one LF. Hashes below use C(x) with no LF; SHA-256 text is 64 lowercase
hex. Array sorting compares exact UTF-8 bytes, never locale or normalized IDs.

## 4. Physical verification and observation semantics

Apply the active ADR 0027 policy matcher to each candidate string before stat,
directory walking, Git or subprocess access. Invalid/unreadable policy refuses;
do not recover identity by reading a forbidden root. Lexically check derived Git
locator destinations before accessing them. Non-current attachment roots are
never probed. Do not scan other chats, transcripts, user configuration or content.

Use bounded no-follow directory/locator checks and a read-only Git identity probe
to establish one physical linked-worktree root, per-worktree Git directory,
common Git directory, and agreement of Git top-level/back-reference/registration.
The implementation must qualify the probe against forbidden derived locators,
symlink aliases, root replacement, Git configuration indirection and unwanted
hook/helper execution before accepting it. Do not assume a command's read-only
name proves its transitive access scope. Unqualified probe shapes refuse.

Use minimal Git environment: no system/global config or system attributes,
no optional locks, prompts, hooks or fsmonitor. No fetch, network, content read,
index update, lease access, adoption or attestation is permitted. Bind the root,
Git-dir and common-dir device/inode identities as decimal strings, plus physical
paths. HEAD OID and nullable detached branch are diagnostic observations; changing
them does not create another physical edge. A successful record does not depend
on branch creation, clean content, or a writer lock over the worktree.

Perform the physical probe before the registry lock and repeat under it before
publication. If the physical binding tuple changes, do not publish a new positive
edge. Capture HEAD/branch from the final probe; changing only those diagnostic
values does not create a new edge or invalidate the association. Bracket native
observations are obtained by the agent before receiver invocation; they do not
hold a host lock. Native attachment/cwd can still change after the final query.
The record is explicitly as-of evidence, never an atomic host+filesystem snapshot.

## 5. Store ABI, publication and freshness

State root: the existing configured machine-local AWA state directory plus
`codex-associations/v1/`; no caller override. This is new bookkeeping state,
separate from all existing native-entry/session/heartbeat/lease/SQLite/v4 stores.
Key K is lowercase SHA256 of C(array)
`["codex-desktop-local", chat_id]`, without LF. Files are `assoc-K.json` and
`assoc-K.lock`; paths never interpolate raw IDs. Directory 0700 and files 0600,
same UID, regular/no-follow/single-link, bounded descriptor reads. No symlinked
writable ancestor, foreign file, malformed state or unsafe lock is repaired.

Stored schema: `awa-codex-association/v1`. Exact top-level keys:
`schema`, `host_scope`, `chat_id`, `trust`, `adapter_revision`, `revision`,
`observation`, `current_edge_key`, `edges`, `history_truncated`.
The literals/ID rules match the request. Revision is positive and AWA-owned;
it is not a native conversation, generation, turn, epoch or permission.

`observation` has exactly `outcome`, `reason`, `reported_started_ms`,
`reported_completed_ms`, `recorded_ms`, `boot_digest`, `continuous_ns`,
`attachment_set_sha256`, `selected_attachment_ids`, `other_attachment_ids`.
The receiver samples `recorded_ms`, boot digest and continuous time together after
its final under-lock validation, immediately before building the postimage. It
rechecks the request's 60 s observation-age bound at that point. Recorded time is
the receiver's observation-processing time, not a claimed native event time;
native reported start/end remain separate and are not authenticated. Negative
observations also receive recorded_ms; unavailable clock fields remain null.
All times are integer; selected/other ID arrays are sorted by ID UTF-8 bytes,
unique and disjoint. `attachment_set_sha256` is SHA256(C(A)), where A is the
complete projected attachment-object array sorted by attachment ID after strict
validation. Compute it from both request snapshots and require equality; it does
not hash chat ID, cwd, timestamps or raw tool JSON. Selected IDs are exactly the
one root group's IDs; other IDs are exactly all remaining array IDs. This digest
is a diagnostic commitment, not independently authenticated source proof. Readers
check its type/shape and ID-set consistency; discarded source paths mean they
cannot reconstruct that source-set commitment from the retained record alone.
For unknown, digest is null, both ID lists are empty, and clock fields may be
null when unavailable. For current, both clock fields are required, boot digest
is 64 lowercase hex and continuous time is an integer in 0..2^63-1. Never persist raw
snapshots or non-current attachment paths. Boot digest and continuous time are
receiver samples used only for cache age, never native chat/host identity.

Each edge has exactly `edge_key`, `root`, `git_dir`, `common_dir`, `root_dev`,
`root_ino`, `git_dev`, `git_ino`, `common_dev`, `common_ino`, `head`, `branch`,
`first_verified_ms`, `last_verified_ms`, `attachment_ids`. Six filesystem numbers
are canonical unsigned decimal strings (`0` or nonzero digit followed by digits,
<=20 digits and <=2^64-1); HEAD is 40/64 lowercase hex and branch
is a trim-stable, control-free string of <=256 UTF-8 bytes or null. Edge key is SHA256 of C(array)
`[host_scope,chat_id,root,git_dir,common_dir,root_dev,root_ino,git_dev,git_ino,common_dev,common_ino]`.
Readers recompute it, validate same-chat ownership and reject duplicate keys.
Current pointer is null or references exactly one edge. Other retained edges are
historical observations; they are not proof that an attachment still exists.
Current requires a non-null pointer; unknown requires a null pointer. Sort stored
edges by edge-key UTF-8 bytes and each edge's attachment IDs by ID UTF-8 bytes.
On positive verification set the edge's last time to receiver `recorded_ms` and
replace its attachment IDs with the selected set; preserve first time, or set
first=last for a new edge. Require first<=last. Positive publication additionally
requires no wall-time reversal relative to the prior record and selected edge;
otherwise commit unknown/clock_unavailable instead. Historical edge times may
exceed a later negative observation's `recorded_ms` after wall-clock rollback;
they remain historical and cannot supply a current-clock claim.

Keep <=16 edges/chat and <=262144 bytes/file. A successful new edge may evict
only oldest non-current history by `(last_verified_ms, edge_key)` until <=16;
set `history_truncated=true` permanently thereafter. Never evict another chat or
infer anything about a worktree from eviction. If the byte cap still cannot be
met, refuse publication unchanged. Historical metadata has no automatic disk
deletion task; a future retention operation is separately scoped. Inspect exposes
history truncation, so the cache is never a complete lifecycle inventory.

Record/refresh holds only its own per-chat advisory lock (<=2 s); it never takes
or substitutes for a worktree/lifecycle/writer lease. Under lock, re-read and
validate complete state and expected revision. Conflict refuses without merging
stale input. Current success updates/creates one edge and sets its pointer;
unknown refresh clears only the pointer and records its closed reason. A valid
refresh with correct chat binding/revision but insufficient native or physical
evidence follows that same unknown transition with a closed uncertainty reason;
it cannot leave a positively current cache after a known conflicting observation.
Invalid packets, unsafe state and lock/revision conflicts leave prior bytes
untouched and return no current claim. Positive create/refresh requires a valid
receiver clock. Valid positive requests that cannot establish an association
return unknown without a file on create, or perform the unknown transition on
refresh once chat/state/revision validation succeeds. Use the applicable closed
reason; do not publish another chat's data or refresh old positive timestamps.
Publish
one canonical sorted compact UTF-8 JSON file plus LF via owned exclusive same-dir
temporary file, file fsync, atomic replacement, parent fsync and bounded read-back.
Create additionally verifies target absence under the lock. Never overwrite an
unexpected symlink, special/foreign file or mismatched chat record.

Return publication success only after replacement, parent fsync, canonical
read-back and required handle cleanup complete under the lock. Before attempting
replacement, a failure preserves prior snapshot bytes; remove only the exact
owned temporary file and return refused/publication_failed. Once replacement is
attempted, any error without proof of a fully completed publication returns
durability_unconfirmed/publication_failed, `revision=null`, `changed=null`,
`complete=false`, empty associations. Complete new bytes may be visible; null
means neither confirmed unchanged nor confirmed durable publication. Do not roll
back over a newer writer. Preserve a primary error while attempting all owned
cleanup; a sole cleanup error is not suppressed. Inspection of visible bytes
never proves a prior fsync succeeded. Lost response/CAS conflict requires inspect
then a fresh revision/evidence packet; no blind retry or exactly-once host claim.

Freshness: the receiver samples a stable current-boot token and suspend-inclusive
macOS continuous clock. Parse bounded `/usr/sbin/sysctl -n kern.boottime` output
(<=256 bytes, 1 s limit) into exact integer seconds/microseconds, then hash C(array)
`[seconds,microseconds]` without LF for the boot token. Continuous nanoseconds use
the existing pure `mach_continuous_time_ns()` calculation or an equivalent tested
pure helper, without initializing ADR 0026 authority. Failure to sample either
refuses positive publication. A reader shows a recent as-of observation only for
the same boot, 0<=age<=300 s, valid wall-time ordering and non-null current edge.
Otherwise show historical/unknown; inspect never writes an expiry transition.
Age includes suspend. Neither timestamps nor clocks prove continuing association.

`inspect --chat-id` reads that keyed record. `inspect --worktree` first checks
the supplied path lexically, then scans at most 256 association files matching
`assoc-[0-9a-f]{64}.json`, in ascending filename ASCII order. Enumerate at most
1024 directory entries before sorting; excess entries/files produce unknown with
limit_exceeded, not a truncated complete list. Ignore valid lock filenames;
unexpected entries make the view incomplete/unsafe_state and are never repaired.
Validate files without following links and match stored roots without target
probing. Root inspection selects at most one edge per chat for that root: its
current edge if matching, otherwise greatest `(last_verified_ms,edge_key)`.
Chat inspection returns all retained edges. Both sort output association items
by `(root,chat_id,edge_key)` using UTF-8 bytes. The result cardinality is <=16 for
chat inspection, <=256 for root inspection, and every response is <=131072 bytes.
If a complete response exceeds its cap, return unknown/limit_exceeded with no
associations and complete=false; never truncate silently. Root scans are not an
atomic multi-chat snapshot and never mean all native chats or sole owner.

Missing/unsafe/unreadable or over-cap state returns unknown, empty associations,
complete=false. An otherwise readable cache with historical/unknown observations
may return its bounded historical items, but complete=false if stale, unknown,
clock-unavailable or history-truncated. Empty state is unknown, not unregistered
host truth and never cleanup clearance. No global index or multi-file transaction.

Responses have exact keys `schema`, `action`, `outcome`, `reason`, `revision`,
`changed`, `complete`, `associations`, `verification_source`, `protection_claim`,
`writer_exclusion_granted`, `cleanup_authorized`. Schema is
`awa-codex-association-result/v1`; source is `trusted-agent-mediated`, and the last
three claims are always false. Outcomes: `recorded_as_observed`, `unknown`,
`historical`, `conflict`, `refused`, `durability_unconfirmed`. Result reasons are
the request uncertainty reasons plus `none`, `invalid_input`, `unsupported_host`,
`policy_refused`, `physical_identity_unavailable`, `unsafe_state`, `lock_busy`,
`revision_conflict`, `limit_exceeded`, `clock_unavailable`, `stale`, `no_record`,
`no_cached_match`, `state_unavailable`, `cached_unknown`, `publication_failed`. Association
items contain only `chat_id`, `root`, `edge_key`, `state`, `as_of_ms`;
state is `recent_as_observed`, `historical`, or `unknown`. No arbitrary errors,
paths other than the queried/recorded association, or raw exceptions escape.
Result `action` is `record`, `refresh` or `inspect`. Complete is boolean and refers
only to the requested local-cache scope, never the native population. Changed is
true only for a fully confirmed publication, false for confirmed no publication,
null only for durability_unconfirmed. Use this exhaustive result matrix:

| Branch | Outcome/reason; exit | revision; changed; complete; associations |
|---|---|---|
| Confirmed positive record/refresh | recorded_as_observed/none; 0 | new revision; true; true; exactly one recent_as_observed current item |
| Confirmed unknown refresh | unknown/closed uncertainty reason; 0 if unknown was requested, otherwise 1 | new revision; true; false; empty |
| Valid but unverifiable create | unknown/closed uncertainty reason; 1 | null; false; false; empty; no file |
| CAS/create-exists/refresh-missing conflict | conflict/revision_conflict; 1 | validated current revision, or null when absent; false; false; empty |
| Invalid request | refused/invalid_input or unsupported_host; 2 | null; false; false; empty; no state access/write |
| Unsafe state, lock busy, limit refusal (record/refresh) | refused/unsafe_state, lock_busy or limit_exceeded; 1 | null; false; false; empty |
| Failure proven before replacement attempt | refused/publication_failed; 1 | null; false; false; empty |
| Failure after replacement attempt, publication not fully confirmed | durability_unconfirmed/publication_failed; 1 | null; null; false; empty; file may have changed |
| Inspect absent state directory or absent requested chat file | unknown/no_record; 0 | null; false; false; empty |
| Inspect existing safe root-query cache with zero files or no matching edges | unknown/no_cached_match; 0 | null; false; false; empty |
| Inspect unsafe/malformed state or read/access failure | unknown/unsafe_state or state_unavailable; 1 | null; false; false; empty |
| Inspect policy or cap failure | refused/policy_refused or unknown/limit_exceeded; 1 | null; false; false; empty |
| Inspect readable matching state | deterministic classification below; 0 | validated chat revision, always null for root query; false; as classified; bounded items |

Inspect classification precedence: policy failure is refused/policy_refused;
unsafe/inaccessible/limit failure is unknown with unsafe_state, state_unavailable
or limit_exceeded respectively. All have no associations and complete=false.
Absent directory/chat file is unknown/no_record; existing root-query cache with
no matching edges (including an empty cache directory) is unknown/no_cached_match.
Both are completed local-cache views with the exact empty-result matrix above,
not observations of native availability. For readable matching
records, classify each edge separately: only its record's current edge with a
current observation, same boot, consistent clocks and age<=300 s is recent.
Other edges are historical, including every edge of an unknown observation.
If the reader clock is unavailable, return unknown/clock_unavailable with only
historical items and complete=false. Otherwise any recent item gives
recorded_as_observed/none; with no recent item but a stored unknown observation,
use unknown/cached_unknown, identifying only the stored observation's uncertainty
without reasserting its past native-source reason as a live finding; with historical
items only, use historical/stale. Any stale/unknown/history-truncated matching
record makes complete=false even when another chat's item is recent; otherwise
complete=true. Item as_of_ms is the edge's last_verified_ms. Thus an unknown
record never projects its old pointer as recent, but another chat's independently
recent cache item may remain visible in a mixed, explicitly incomplete root view.
`native_unavailable` is reserved for reporter-supplied record/refresh uncertainty;
inspect never returns it. Every inspect branch is read-only. For no_record,
no_cached_match, state_unavailable and unsafe_state, revision=null, changed=false,
complete=false and associations=[] exactly; no absent-state directory is created.

For publication, new revision is previous+1 (1 on create); overflow refuses
limit_exceeded. Re-reading a record never increments revision or refreshes age.
For mutation replies, complete describes the requested current observation, not
all history: confirmed positive replies are complete; negative replies are not,
even though their bookkeeping publication completed (`changed=true`). On inspect,
an item's recent state is permitted only for its record's current edge and when
that observation passes all freshness checks.

## 7. Ordered implementation and delivery

1. **Document closure.** Independently review the canonical paired draft postimages.
   Use the enabled doc-warden authoring profile and existing approved planning
   requirements. Concrete semantic acceptance names exact final artifacts/digests
   and the agent-mediated trust/limits. It does not arise from authoring enrollment,
   drafting instructions, technical review or merge of unaccepted drafts.
2. **Parser and physical probe.** After exact implementation GO, add a separate
   association module and test-only injected native/clock/Git interfaces. Qualify
   strict parsing and physical-path access under AWA-AS-01/02/04; do not retrofit
   the Cursor payload parser. If a probe cannot satisfy no-touch, refuse that
   input shape rather than weakening policy.
3. **Store and view.** Add the per-chat store/lock/CAS, bounded history, read-only
   inspect and closed projection. Exercise AWA-AS-03/05/06/07/09 and all fault
   cuts in disposable synthetic state. No root lease, SQLite migration or daemon.
4. **CLI integration and regression.** Thin entrypoint dispatch only; no automatic
   bootstrap, hook, installer activation or MCP mutation tool. Prove AWA-AS-08,
   focused new tests, current owner full `make verify-pre-pr`, frozen-byte scope
   and doc-warden checks. Publish ready PR; App owns approval and native merge.
5. **Qualification then activation decision.** Independently review the complete
   implementation. A metadata-only native canary can qualify AWA-AS-10 after its
   concrete scope is fixed; any live record writes, installation/release or host
   instruction changes require their named scope/acceptance. Keep private state
   untouched until that point. Verify delivery/qualification/activation separately.

Expected runtime source surface is one dedicated association parser/physical
