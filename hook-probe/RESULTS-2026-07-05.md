## Findings mapped to the ledger

### L3 — Desktop event set + `beforeSubmitPrompt` payload shape — **Verified (probe, Desktop)**
- The five events above fired on Desktop with the field shapes shown. Crucially
  `beforeSubmitPrompt` carries the **raw `prompt` text plus an `attachments` field**
  (empty in these runs) and **no classifier** — confirming L3's "intent detection is
  DIY, Desktop-only." Evidence: `events.jsonl` records #1,#2,#3,#5,#6 + the
  `analyze.py` per-event table (surface = **Desktop**).

### Kernel gate — `beforeShellExecution` fires as a project hook on Desktop — **Verified (probe, Desktop)**
- `beforeShellExecution` fired from the harness repo's project-level `.cursor/hooks.json`
  with a payload carrying **`command` + `cwd` (+`sandbox`)** — the exact fields the AWA
  kernel guard classifies. This is the load-bearing fact that a **project-level** shell
  gate actually receives the command on Desktop. Evidence: `events.jsonl` record #3.
- **Residual (cloud):** that a **committed** project hook fires on a real **cloud VM**
  (as opposed to a Desktop project hook) is the L10 cloud claim — **NOT** proven here
  (Desktop runs both committed and uncommitted project hooks). See "Still open."

### L4 — `afterFileEdit` is observation-only (a post-action `deny` is ignored) — **Verified (Desktop, operator-observed); log-record not retained**
- **Operator observation (live, Desktop):** the probe returned
  `{"permission":"deny", …}` from `afterFileEdit`, yet the edit **landed** — the target
  file changed on disk. **On-disk corroboration:** `~/awa-hook-probe-uat/sample.txt`
  is mutated to `edit-me: 2` (from its seed value), i.e. an agent edit persisted.
- **Honest evidence texture:** the `afterFileEdit` **hook invocation was NOT retained**
  in the captured `events.jsonl` (which holds only the 5 event types above). So this
  row rests on **(a)** the live operator observation, **(b)** the on-disk file mutation,
  and **(c)** the L2 doc-snapshot fact that `afterFileEdit` is a post-action hook with
  **no honored permission output** — **not** on a retained hook record.
- **Design conclusion (unchanged, now empirically corroborated):** confirms the AWA
  **X2 detect-only** design — a native edit to a primary checkout can be *detected* via
  the `afterFileEdit` receipt but **cannot be pre-blocked**; `stop` likewise cannot block.
- **Recommended follow-up:** a targeted re-drive (edit one file with the harness wired)
  to **capture the `afterFileEdit` record in `events.jsonl`** would close the log-level
  evidence for this row. Same for `beforeReadFile` (see below).
